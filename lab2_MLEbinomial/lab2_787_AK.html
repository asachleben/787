Binomial Models

This week in lab we are shifting towards modeling with binary outcomes, or outcomes that can take on only one of two mutually exclusive values. Binary outcomes are exremely common in political science, so knowing how to work effectively with them is critical.

From POLI 784 you already know how to estimate a linear regression using lm(). So, one reasonable starting point might be to wonder why we wouldn’t also use OLS when our outcome variable is binary? As Santiago discussed in lecture, you actually can, however this creates some important problems. We’ll use those problems to motivate two common binomial models, the logit and the probit, and learn how to estimate them using glm().

Finally, we’ll also look under the hood at how these models are estimated, and we’ll use optim() to manually estimate the same logit model we fit using glm().

We could estimate the relationship between political interest and turnout using the lm() command you are familiar with. This problem is particularly pronounced at the extremes of our data (those with an interest of 0 or 6). As you can see, OLS does not know that our dependent variable represents a binary outcome. It simply fits the best linear relationship through the data, and nothing prevents that line from extending below 0 or above 1. This is one reason we often turn to models specifically designed for binary outcome variables.

Generalized Linear Models

One way to estimate models for binary outcomes in R is with the glm() command. The basic syntax for a glm() should look pretty familiar.

glm(
  outcome ~ predictor,
  data = data,
  family = ...(link = "...")
)

The important new piece is the family argument. The family tells R about the distribution of out outcome variable, and the link function we want to use. For a binary dependent variable, we use the binomial family. Two of the most common link functions are logit and probit. Let’s estimate a logit model using our fake turnout data.

# estimate logit model on turnout data
turnout_logit <- glm(
  turnout ~ interest,
  data = turnout_data,
  family = binomial(link = "logit")
)

summary(turnout_logit)

Interpreting Logit & Probit Models

Logit and probit models give us predicted probabilities that stay between 0 and 1. However, the cofficients are no longer as straightforward to interpret as the coefficients from out linear probability model. For a logit model, the coefficients represent changes in the log-odds of the outcome:

\[ \log\left(\frac{p_i}{1-p_i}\right)=X_i\beta. \]

Log-odds aren’t exactly the most intuitive quantity to communicate, so one thing we can do is exponentiate the coefficients to convert them into odds ratios. Odds ratios have a useful reference point:

  • An odds ratio of 1 indicates no change in the odds.
  • An odds ratio greater than 1 indicates increasing odds.
  • An odds ratio less than 1 indicates decreasing odds.

Let’s focus on pop_attacks. Inspect and interpret the estimate on pop_attacks.

# inspect logit coefficient for attacks on population
coef(model_logit)["pop_attacks"]
#>>> pop_attacks 
#>>>   0.3111794

# convert coefficient into odds ratio
exp(coef(model_logit)["pop_attacks"])
#>>> pop_attacks 
#>>>    1.365034

# calculate percentage change in odds
100 * (
  exp(coef(model_logit)["pop_attacks"]) - 1
)
#>>> pop_attacks 
#>>>    36.50342

It’s important to remember that odds are not probabailities. Odds ratios can be useful, but we often ultimately want to say something about the predicted probability of observing our outcome. Notice that all of these values fall between 0 and 1. This is exactly what R was doing earlier when we specified predict(model_logit, type = “response”). So, plogis() is the inverse-logit transformation. It takes an unbounded linear prediction and maps it onto a valid probability between 0 and 1. The same basic process occurs with a probit model. The difference is that the probit uses the CDF of a standard normal distribution rather than the logistic distribution. To estimate predicted probabilities for a probit model, we therefore use pnorm() rather than plogis().

Maximum Likelihood Estimation

So far, glm() has done all of the estimation for us. But, where did those particular coefficient values come from? For our logit model, we assume that each observation has some probability \(p_i\) of having AUC = 1. For a binary outcome, the likelihood contribution for observation \(i\) can be written as:

\[ p_i^{y_i}(1-p_i)^{1-y_i}. \]

If \(y_i=1\), this becomes \(p_i\). If \(y_i=0\), it becomes \(1-p_1\). Across all of our observations, the likelihood therefore is: \[ L(\beta) = \prod_{i=1}^{N} p_i^{y_i}(1-p_i)^{1-y_i}. \]

Our goal is to find the values of \(\beta\) that make the data we actually observed as likely as possible, or the maximum likelihood estimation (MLE). Rather than multiplying all of these probabilities together, we generally work with the log-likelihood:

\[ \log L(\beta) = \sum_{i=1}^{N} \left[ y_i\log(p_i) + (1-y_i)\log(1-p_i) \right]. \]

At the end of the day, MLE is therefore an optimization problem, and the task is to find the parameter values that maximize the likelihood function. Usually, convenient functions like glm() do this work for us.

But we can also do it ourselves. This is tool is particularly important if we are doing something such as estimating a regression for a variance, because this is something glm() cannot do. However, `optim() can!

Optimization

The optim() function is a general-purpose optimization function in R. Unlike glm(), optim() has absolutely no idea that we specifically want to estimate a logit model. We’re going to have to tell it exactly what function we want it to optimize. For this example, our goal is to reproduce the same logit model we already estimated using glm(), but this time we’ll do it using optim().

First, we’ll extract the outcome and design matrix that glm() actually used.

# extract data used to estimate logit model
model_data <- model.frame(model_logit)

# extract dependent variable
y <- model.response(model_data)

# create design matrix
X <- model.matrix(model_logit)

# inspect first few rows
head(X)
#>>>   (Intercept) tribut_2_log tribut_2_log_sq pop_attacks disbogota drugs  pop_log
#>>> 1           1     11.02993        121.6595           4   264.339     0 14.39967
#>>> 2           1     11.23646        126.2581          10   264.339     0 14.42103
#>>> 3           1     11.45685        131.2594           9   264.339     0 14.44265
#>>> 4           1     11.76960        138.5235           8   264.339     0 14.46411
#>>> 5           1     12.06222        145.4971           6   264.339     0 14.48503
#>>> 6           1     12.18601        148.4988           4   264.339     0 14.50504

Notice that the design matrix includes a column of 1s for our intercept along with each of our predictor variables. We next need to write the function we want optim() to optimize. There are a few piece worth thinking about here. First, eta <- X %*% beta calculates \(X\beta\) then `p <- plogis(eta) converts those predicted log-odds into probabilities. Finally, the dbinom() function calculates each observation’s contribution to the binomial log-likelihood. The syntax for optim is below:

Note: optim()` minimizes a function by default. We want to maximize the log-likelihood, so instead we minimize the negative log-likelihood. The parameter values that accomplish those two things are the same.

# write negative log-likelihood function
logit_nll <- function(beta, y, X) {

  # calculate linear predictor
  eta <- X %*% beta

  # transform linear predictor into probabilities - what function does this?
  p <- plogis(eta)

  # calculate negative log-likelihood
  nll <- -sum(
    dbinom(
      y,
      size = 1,
      prob = p,
      log = TRUE
    )
  )

  # return negative log-likelihood
  return(nll)
}

Optim() Exercise

Now, let’s optimize! optim() has several important arguments:

  • par: our starting values for the parameters
  • fn: the function we want to optimize
  • method: the optimization algorithm
  • hessian: whether we want R to return the Hessian matrix

We’ll use "BFGS", which is a quasi-Newton optimization method. We’ll use optim() to try to estimate the same glm model that we fit in the previous example about paramilitary groups in Colombia.

# create starting values
starting_values <- rep(
  0,
  ncol(X)
)

# estimate logit model using optim()
optim_logit <- optim(
  par = starting_values,
  fn = logit_nll,
  y = y,
  X = X,
  method = "BFGS",
  hessian = TRUE
)

Standard Errors

In the above code, we set hessian = TRUE when we called optim(). The Hessian contains information about the curvature of our likelihood function around its optimum. We can use its inverse to recover our estimated variance-covariance matrix and, from there, our standard errors. We can then compare the standard errors from our previoulsy estimated logit model and the optim()function we just ran.

# calculate standard errors from optim hessian
optim_se <- sqrt(
  diag(
    solve(optim_logit$hessian)
  )
)

# compare standard errors
cbind(
  GLM = sqrt(diag(vcov(model_logit))),

Flexibility of optim()

Given this exercise, it might be reasonable to think, “Why did we just write all of that code when glm() estimated the same model in about three lines?” For a standard logit or probit model, you probably should use glm().

The main advantage of optim() is its flexibility. glm() knows how to estimate a particular set of generalized linear models. If the model you want fits within that framework, great. But suppose we wanted to specify a model in which not only the expected value of \(Y\) depends on predictors, but the variance itself also has a regression model. For example:

\[ Y_i \sim N(\mu_i,\sigma_i^2) \] where: \[ \mu_i = X_i\beta \] and: \[ \log(\sigma_i^2)=Z_i\gamma. \]

Now we have one set of coefficients predicting the mean and another set of coefficients predicting the variance. A standard call to glm() does not allow us to specify an arbitrary second regression for the observation-specific variance. But if we can write down the likelihood for that model, we can write a function containing both \(\beta\) and \(\gamma\) and pass it to optim().

This is the kind of application where knowing how to use a general optimizer becomes particularly useful. You won’t normally want to reinvent a model for which a reliable R package already exists. But understanding optim() gives you the ability to estimate models that don’t fit neatly into the convenient functions you’re used to.
